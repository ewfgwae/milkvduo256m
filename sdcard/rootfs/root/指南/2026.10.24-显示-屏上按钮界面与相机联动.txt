     救回来, 但要拆机取卡、代价高。
  2) 改小核固件一律走"热更"(见 2026.9.28-小核-帧率修复与热更.txt 第五章) ——
     它不碰 fip.bin、不重启系统。
  3) lcd_sender mon 与 rtsp2lcd 互斥(共用 cmdqu 8 槽, 打满后永久 ENOBUFS 不自愈),
     唯一解药是热更一次小核固件。mon 已从开机自启摘除, 不要再常驻它。

  一、环境与约定
================================================================================

1.1 上电后屏上是什么(★ 与 2026.10.3 之前的行为不同了)
--------------------------------------------------------------------------------
  1) 上电默认是 **UI 待机页**: 深色底, 标题「智能看家」, 下方副标题 MILK-V DUO 256M,
     中间一个大按钮「相机画面」, 按钮下有状态栏文字「待机」, 左下角小字提示
     `lcd_sender cam on / off`。右下角 OSD(帧率/占用率)仍在, 不受影响。
  2) 点按钮(或终端 cam on)后的状态流转:
       待机 -> 按下动画(约 0.2s) -> 启动中(转圈 spinner, 状态字「正在取像...」)
       -> 首帧到达, UI 整页隐藏, 摄像头画面满屏;
       15s 内首帧没到 -> 状态栏红字「超时，再来一次」, 回待机;
       cam off -> 画面消失, 回按钮页, 状态字「已停止」。
  3) 启动中再按按钮/再来 BTN 一律忽略(防连打); 画面模式下来 BTN 也忽略。
     超时红字出现后, 如果首帧这时才到, **画面仍会自动进**(不是死状态)。
  4) 屏幕仍由小核(C906L)独占, 这页 UI 在小核固件的 lvgl_task.c 里, 与大核无关;
     大核只通过两条新命令"点"它(见 1.3)。

1.2 终端入口命令(★ 最常用, 在板上一条命令搞定)
--------------------------------------------------------------------------------
  1) 开画面(等于替你按下屏上按钮):
       /root/lcd_sender cam on
     它做两件事: 先发 BTN 给小核(屏上立刻出按下动画), 再后台起 /root/lcdcam.sh 推流循环。
  2) 关画面:
       /root/lcd_sender cam off
     顺序纪律: **先**跑 lcdcam.sh stop 等它收干净, **再**发 UI 命令回按钮页。
     顺序反了的话下一帧 CAM 又会把刚回来的 UI 盖住。这两条命令内部已按此实现。
  3) 重复 cam on 是安全的: lcdcam.sh 的 start 子命令会扫 /proc 发现循环已在跑就不重复起。
  4) 手动控制推流循环(不经按钮):
       sh /root/lcdcam.sh start        # 后台常驻循环(断线自动重连)
       sh /root/lcdcam.sh stop         # 停循环 + rtsp2lcd
       sh /root/lcdcam.sh stopall      # 连取流服务 sample_vi_fd 一起收

1.3 新增的大小核命令与共享内存改动
--------------------------------------------------------------------------------
  1) LCD_CMD_BTN = 0x49: 大核 -> 小核, 触发按钮按下动画 + 进入"启动中"。小核**不回 ack**
     (与 CAM 同纪律, 不占 cmdqu 回执)。
  2) LCD_CMD_UI = 0x4A: 大核 -> 小核, 退出画面模式回按钮页(显示「已停止」)。
  3) lcd_shm.h 两份副本(小核 comm 侧 / 大核 lcd_sender 侧)加了上面两个命令号, 并把
     stat.reserved[0] 改名 ui_event —— 小核独占写, 按钮将来被触摸点中时计数 +1,
     给大核守护进程轮询用(触摸方案, 见 PC 仓库 plans/06, 尚未实施)。
     ★ 两份 lcd_shm.h 必须逐字节一致, 改一处必同步另一处。
  4) 触摸驱动骨架 lcd_touch.c/h 已在小核固件里(注册 indev, 恒返回"未按下"),
     芯片型号未定, 等确认后填充。

1.5 中文文案的硬约束(SIMSUN16 字库只有 1412 个码点)
--------------------------------------------------------------------------------
  1) 小核中文字体用的是 LVGL 自带 SIMSUN_16_CJK, 实际只覆盖 **1412 个码点**(偏日文
     JIS 常用汉字), 简体动词大面积缺字: 「启/摄/识/别/请/稍/试/监/频/开」等全缺,
     繁体「監」也缺。写了不在库里的字, 屏上就是方块。
  2) 因此文案是**全简体定稿**(逐字验证在库), 不要随手改字:
       标题=智能看家  按钮=相机画面  待机=待机  启动中=正在取像...
       已停止=已停止  超时(红)=超时，再来一次
  3) 以后要改文案, 先在 PC 上解析 lv_font_simsun_16_cjk.c 的 cmap 验证每个字在库,
     再动代码(验证思路见 PC 仓库 plans/05 的 PLAN.md Phase 0)。

1.6 longrun.sh 的一个坑(今天长跑时暴露, 本轮没修它)
--------------------------------------------------------------------------------
  1) /root/longrun.sh 开头用 `killall lcdcam.sh` 清场, 但 busybox killall 按 argv[0]
     匹配, **打不中 `sh /root/lcdcam.sh` 这种进程**(循环活着), 它会在 2s 后把 rtsp2lcd
     重新拉起来; 而 RTSP 服务端只有一个客户端名额, 于是 longrun 自己的 rtsp2lcd
     被挤在门外, run.log 刷满"停顿 Ns 无数据"——**流本身没断**, 是 longrun 的监测瞎了。
  2) 以后跑 longrun 前先正规清场:
       /root/lcd_sender cam off
  3) 判断画面是否真的在动, **只认探针 [17]**(大核提交帧号)在以约 +30/s 涨;
     run.log 的异常行/停顿行在双客户端挤占时会骗人。
