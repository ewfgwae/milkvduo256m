1.1 退出按钮是什么、怎么触发
--------------------------------------------------------------------------------
  1) 位置: 进入画面模式(cam on 首帧到达)时, 屏右上角出现「退出」小按钮,
     盖在画面之上、OSD 之下; 退画面时随画面一起删掉。
  2) 指令触发 = 平时的关画面命令, 它内部第一步就是"按下"这个按钮:
       /root/lcd_sender cam off
     三步顺序: 发 LCD_CMD_EXIT_BTN(屏上按钮出按下动画, 300ms 弹起) ->
     sh /root/lcdcam.sh stop 等收干净 -> 发 LCD_CMD_UI 回按钮页「已停止」。
  3) 也可以绕过 lcd_sender 直发 0x4B(只闪动画, 不退画面, 见 1.2):
       python3 - <<'PYEOF'
       import os, fcntl
       buf = bytearray(bytes([6, 0x4B, 0, 0, 1, 0, 0, 0]))
       fd = os.open("/dev/cvi-rtos-cmdqu", os.O_RDWR)
       fcntl.ioctl(fd, 0x40087201, buf)
       PYEOF
     发完画面**继续在动**(判据: 探针 [17] 仍在 +30/s 涨、[16] 仍 = 1)。
  4) 待机时发 0x4B 无害: 小核忽略, 不崩(判据: [2] 主循环仍在涨)。

1.2 协议与状态机语义(为什么 0x4B 只做动画)
--------------------------------------------------------------------------------
  1) LCD_CMD_EXIT_BTN = 0x4B: 大核 -> 小核, **纯视觉反馈**, 小核不退画面、
     不回 ACK(同 BTN/CAM 纪律)。真退画面仍是 LCD_CMD_UI(0x4A)。
  2) 停不停链路是大核的事: 若 0x4B 就退画面, 谁直发它都会让"屏已回 UI、
     大核还在推流"两边状态错位(下一帧 CAM 又抢回画面模式)。
  3) 触摸物理按下(CLICKED)只计 stat.ui_event +1(小核独占写, 64B 线 flush),
     由 plans/06 的大核守护进程轮询后停链路+发 UI —— 小核绝不在 LVGL
     回调里碰 cmdqu(8 槽老坑)。
  4) 0x4B 在"按下中"再来一次会被忽略(300ms 弹起内不重入)。

1.4 上电启动页(plans/05 Phase 6, 2026-10-25 凌晨落地)
--------------------------------------------------------------------------------
  1) 是什么: 小核固件 build 0x484A000F 起上电不再直接显示完整按钮 UI, 而是黑底
     + 56px 转圈 + 「正在初始化...」启动页; 大核(A53/Linux)就绪前它一直转, 无超时。
  2) 为什么: 之前大核没起来屏上就挂着完整按钮页, 观感差; 启动页表达"系统正在起"。
     文案定「正在初始化...」是因为「正在启动」的 启/动 都不在 SIMSUN16 字库
     (2026-10-25 逐字预检; 在库备选: 正在等待... / 等待中...)。
     ★ 订正(01:2x, 见变更记录末条): 早期预检脚本有假阳性缺陷; 位图级复检后
     「正在初始化」六字确在库, 但 ASCII 句点 '.' **不在库** —— 0x484A0010 起
     文案改为不带句点的「正在初始化」, 版式同步升级(渐变底+标题)。
  3) 怎么离页(小核 lvgl_task.c 的 boot_leave(), 三个入口):
     a) LCD_CMD_UI(0x4A) —— auto.sh 热更成功后自动发 / 手动 lcd_sender ui /
        cam off 末步 -> 按钮页, 状态「待机」;
     b) LCD_CMD_BTN(0x49) —— cam on 当首个命令: 先出按钮页再播按下动画;
     c) 首帧 CAM —— 不发 BTN 直接起 rtsp2lcd: 直进画面(启动页必须删, 不能
        盖在画面上)。
  4) MON / INIT / PING 故意不离页: mon 是诊断工具且与 rtsp2lcd 互斥; INIT 是
     lcd_sender rtos 热更后的 state 轮询, 不能让它把启动页顶掉。
  5) 手动热更后屏幕停在启动页属预期, 回按钮页发一条:
       /root/lcd_sender ui
  6) 冷启动 0 ~ 热更完成(约 30~40s)屏上是 fip.bin 老固件(0x484A0009, 无启动页),
     仍显示老 UI 页 —— 这段只有重烧 fip 才能改(铁律不动)。冷启全程观感:
     老 UI 页 -> 启动页闪现 1~2s -> 按钮页(热更+ui)。
  7) 判据: 启动页在转 = 探针 [7] 数百 fps(实测 ~500, spinner 在画); 已离页回
     按钮页 = [7] 回 1.0fps(读数 0xA); 画面模式照旧看 [16]/[17]。
