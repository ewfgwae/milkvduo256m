# PLAN.md — 06 触摸：分阶段实施计划与测试流程

★ 前置：`plans/05` 已实施完（骨架 + ui_event 通道就位）。芯片型号未定，Phase 0 是用户的动作。

## Phase 0 — 确认触摸芯片（用户动作，决定后面走哪条路）

1. 看屏模块背面丝印 / FPC 软排线上的标注：
   - 有 `T_CLK/T_CS/T_DIN/T_DO/T_IRQ` 五根丝印 → 电阻屏，芯片按 XPT2046 路线；
   - 有 `SDA/SCL/INT/RST` 四根 → 电容屏，找 GT911/GT9xx 或 FT6236/FT6336/FT6206 字样；
   - 都没有 → 把模块型号/购买链接发给开发会话一起判断。
2. 把结果回填 `AGENTS.md` 的候选表（划掉不用的）。

## Phase 1 — 小核 GPIO 输入能力

改动：`driver/gpio/src/gpio.c` 扩 `gpio_direction_input` / `gpio_get`（保持读-改-写）。

**验收 / 测试流程**：
- [ ] 选定脚接一个轻触开关到 GND（临时），`gpio_direction_input` + 轮询 `gpio_get`，
      小核探针或日志能看到按下/弹跳；屏驱动不受影响（彩条/画面正常）。

## Phase 2 — 触摸芯片驱动（三选一）+ 校准

改动：只改 `lcd_touch.c/.h` 的实现（接口不动）。

- **XPT2046**：位邦 SPI 读 X/Y/pressure（命令字 0x90/0xD0 一类，以手册为准）；IRQ 脚低电平
  表示按下，轮询即可（不需要真中断）；去抖 10~20ms。
  ★ 校准流程（电阻屏必做）：
  1. 屏上依次显示左上/右上/左下/右下/中心五个十字靶（LVGL 画）；
  2. 每个靶记录触摸 raw 值（人工按住，探针读回）；
  3. 最小二乘解 raw→屏幕 的仿射系数（6 个数），写死进 `lcd_touch.c`，回填本文件。
- **GT911**：位邦 I2C，复位时序按手册（RST 低 → INT 拉特定电平选地址 0x5D/0x14 → RST 高），
  轮询 INT 或状态寄存器读坐标点；坐标通常已是芯片分辨率，做一次线性映射到 320×240 即可。
- **FT6x06**：位邦 I2C（地址 0x38），读状态寄存器 + 点坐标寄存器，线性映射同上。

**验收 / 测试流程**：
- [ ] `lcd_touch_read()` 返回的坐标与手指位置一致（四角 + 中心五点，偏差 ≤ 一个按钮的 1/4）；
- [ ] 抬手后 100ms 内回到"未按下"；
- [ ] 按 `plans/05` 的 UI：点按钮 → 按下动画 + 状态切换（此时大核守护没上，预期走到
      「启动超时」回待机——这是**正确行为**，说明链路通）；
- [ ] 回归：OSD/画面模式不受触摸轮询影响（`[2]` 圈速不塌、画面 33fps 正常）。

## Phase 3 — 大核守护进程 cam_btnd（闭环）

改动：新文件 `tools/cam_btnd.c`（大核，照 `lcd_sender.c` 的 /dev/mem 映射写法）。

- 200ms 轮询 `stat.ui_event`；变化 → toggle：不在推流就 `sh /root/lcdcam.sh start`，
  在推流就 `sh /root/lcdcam.sh stop`（等返回）+ 发 `LCD_CMD_UI`（借用 lcd_sender 或自己 ioctl，
  纪律照模块 02）。
- `stat` 线是大核只读——**绝不写**；映射用 `O_SYNC` 非缓存。

**验收 / 测试流程**：
- [ ] 点按钮（真触摸）→ 全自动出画面（含按下动画）；再点 → 停画面回 UI；
- [ ] 与终端 `lcd_sender cam on/off` 混用不冲突（守护进程 toggle 前先读当前状态）；
- [ ] 守护进程跑 1 小时无泄漏（`ps` 稳定、无僵尸子进程——system() 调的 shell 要 wait 干净）；
- [ ] 拔掉触摸排线：守护进程读不到事件，一切如常（轮询超时无副作用）。

## Phase 4 — 画面模式屏上「停止」按钮（补齐 plans/05 留的尾巴）

**验收 / 测试流程**：

- [ ] pill 不遮挡画面主体、不参与帧刷新（只状态切换时重画一次）。
